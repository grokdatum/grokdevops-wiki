Learning Paths¶

Curated sequences for common career goals. Each path lists topics in optimal order with estimated study hours. Hours are for first-pass reading + exercises; mastery takes more.

All paths assume basic computer literacy (comfortable with a text editor, understands files and directories, has used a terminal at least a little).

Path: Junior SRE → On-Call Ready (8–12 weeks)¶

The fastest route to being useful in an SRE role. Optimized for breadth over depth — enough to diagnose common incidents without panicking.

Phase 1: Linux Foundations (2 weeks)¶

Week Topic Est. Hours Why Now
1 linux-ops 5h Everything runs on Linux — this is bedrock
1 linux-users-and-permissions 2h File perms and sudo are daily friction
1 systemctl-journalctl 2h How to inspect running services and their logs
1 process-management 2h What's eating my CPU/memory
2 linux-ops-systemd 3h How init works; unit files; dependency ordering
2 linux-logging 2h syslog, journald, log rotation
2 linux-memory-management 2h OOM kills, swap, why things crash
2 environment-variables 1h How config flows into processes

Phase 2: Networking Essentials (1.5 weeks)¶

Week Topic Est. Hours Why Now
3 networking 4h OSI model, how packets flow, LAN vs WAN
3 subnetting-and-ip-addressing 3h It's always a subnet mask
3 dns-ops 3h It's always DNS
4 tcp-ip-deep-dive 3h TCP handshake, ports, sockets — what netstat shows
4 tls 2h HTTPS, certs, why things say "certificate expired"
4 ssh-deep-dive 2h Key auth, tunnels, ProxyJump

Phase 3: Containers and Kubernetes Basics (3 weeks)¶

Week Topic Est. Hours Why Now
4 docker 4h Images, containers, volumes, networking basics
5 k8s-ops 5h Pods, deployments, services — the daily vocabulary
5 k8s-pods-and-scheduling 3h Why pods don't schedule; resource limits
5 k8s-ops (Probes) 2h Liveness and readiness — why pods restart
6 oomkilled 2h The most common K8s failure mode
6 crashloopbackoff 2h Second most common failure mode
6 k8s-services-and-ingress 3h How traffic reaches your app
6 k8s-debugging-playbook 3h Systematic debugging runbook

Phase 4: Observability (2 weeks)¶

Week Topic Est. Hours Why Now
7 monitoring-fundamentals 3h Metrics, dashboards, the four golden signals
7 prometheus-deep-dive 4h PromQL, scrape configs, recording rules
7 alerting-rules 2h Writing alerts that don't page at 3am for nothing
8 logging 3h Structured logs, log levels, searching logs
8 slo-tooling 2h Error budgets, burn rate alerts
8 debugging-methodology 2h Scientific method for production incidents

Phase 5: On-Call Readiness (1.5 weeks)¶

Week Topic Est. Hours Why Now
9 incident-triage 3h Structured approach to "something is on fire"
9 incident-command 2h Roles, communication, running a bridge
9 runbook-craft 2h Writing runbooks people actually use
10 sre-practices 3h Error budgets, toil reduction, blameless culture
10 postmortem-slo 2h Writing actionable post-mortems

Capstone: Run a production-readiness assessment at training/library/assessment/production-readiness/

Path: Breaking Into DevOps (16–20 weeks)¶

For people starting from scratch — career changers, bootcamp grads, and self-taught engineers who want a dependency-correct path into their first DevOps role.

Time: 16–20 weeks, 60–90 min/day, 5 days/week Total estimated hours: ~180–220h Best for: Career changers, bootcamp grads, self-taught engineers breaking into DevOps from scratch Prerequisites: Basic computer literacy (terminal, text editor, files/directories) Post coverage: Covers every item from the "Key Advice for Getting Into DevOps" checklist, reordered for dependency-correct learning

Phase 1: Linux, Git & Scripting (Weeks 1–4)¶

Week Topic Est. Hours Why Now
1 linux-ops 5h Everything runs on Linux — this is bedrock
1 linux-users-and-permissions 2h File perms, sudo, ownership — daily friction
1 systemctl-journalctl 2h How to inspect running services and their logs
1 process-management 2h What's eating CPU/memory, how to stop it
2 linux-ops-systemd 3h Init system, unit files, dependency ordering
2 linux-ops-storage 2h Disks, filesystems, mount points
2 advanced-bash 4h Loops, functions, error handling, pipes
3 python-infra 3h Python for automation — scripting, not software engineering
3 git 3h Version control basics — commit, branch, merge
3 git-advanced 2h Rebase, cherry-pick, reflog — recover from mistakes
4 yaml-json-config 2h The config formats behind everything in DevOps

Hands-on: Bash exercises levels 01–05, Git drills (training/library/drills/git_drills.md), Skillcheck: linux.fundamentals (training/library/skillchecks/linux.fundamentals.md) Flashcard decks: linux-fundamentals.tsv, linux-kernel.tsv, git.tsv Exit criteria: Navigate the CLI without a cheat sheet, write a 50-line Bash script with error handling, use git reflog to recover a lost commit Post coverage: Linux CLI mastery, Bash scripting, Python scripting, Git

Optional: powershell — 2h if targeting Windows-heavy environments

## Objective
Install metrics-server so HPA can read CPU/memory metrics and scale

## Hint 1
🔍 Observation Hint:

Check the HPA status:
`kubectl get hpa -n k8squest`

Look at the TARGETS column. Do you see "<unknown>/50%"?

Describe the HPA:
`kubectl describe hpa web-backend-hpa -n k8squest`

Look at the Conditions section. What error message do you see?

Try getting pod metrics:
`kubectl top pods -n k8squest`

Does it work?

## Hint 2
🧭 Direction Hint:

The error likely says: "unable to get metrics for resource cpu" or "the server could not find the requested resource (get services http:heapster:)"

This means Kubernetes can't get CPU/memory metrics because **metrics-server** is not installed!

Check if metrics-server exists:
`kubectl get deployment metrics-server -n kube-system`

If you get "NotFound", that's your problem. HPA needs metrics-server to function.

## Hint 3
💡 Near-Solution Hint:

Install metrics-server for kind/local clusters:

1. Download the metrics-server manifest:
   `curl -Lo metrics-server.yaml https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml`

2. For kind/Docker Desktop, add `--kubelet-insecure-tls` flag:
   `kubectl patch deployment metrics-server -n kube-system --type='json' -p='[{"op": "add", "path": "/spec/template/spec/containers/0/args/-", "value": "--kubelet-insecure-tls"}]' --dry-run=client`

3. OR easier - apply this one-liner:
   ```bash
   kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
   kubectl patch deployment metrics-server -n kube-system --type='json' -p='[{"op": "add", "path": "/spec/template/spec/containers/0/args/-", "value": "--kubelet-insecure-tls"}]'
   ```

4. Wait for metrics-server to start:
   `kubectl wait --for=condition=available --timeout=60s deployment/metrics-server -n kube-system`

5. Verify HPA now works:
   `kubectl get hpa -n k8squest`

TARGETS should now show actual CPU percentage!

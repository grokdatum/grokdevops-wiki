📝 Key Observation:
In Kind (single-node), ReadWriteOnce works because all pods are on the same node.
But in production multi-node clusters, pods on different nodes can't mount RWO volumes!

🤔 Questions:
• What is ReadWriteOnce? (Hint: one NODE, not one pod)
• What is ReadWriteMany?
• Which mode do you need for shared storage across nodes?

## Hint 2
🎯 HINT 2: Understanding Access Modes

The problem is the access mode is wrong for multi-node shared storage!

📚 Access Modes Explained:

**ReadWriteOnce (RWO)**
- Volume can be mounted by ONE node only
- Multiple pods on SAME node can share it
- Most common mode, works with most storage types
```yaml
accessModes:
  - ReadWriteOnce  # ❌ Not for multi-node deployments with shared storage
```

**ReadWriteMany (RWX)**
- Volume can be mounted by MULTIPLE nodes simultaneously
- All pods across any nodes can share it
- Requires network storage (NFS, CephFS, etc.)
```yaml
accessModes:
  - ReadWriteMany  # ✅ Perfect for shared content across nodes
```

**ReadOnlyMany (ROX)**
- Multiple nodes can mount, but read-only
- Good for static content distribution

🔍 Your Situation:

In Kind (single-node):
- All 3 pods run fine with ReadWriteOnce (all on same node)
- But this is WRONG for production multi-node clusters!

In Production (multi-node):
- Deployment with 3 replicas spreads across nodes
- With ReadWriteOnce, only pods on first node can mount
- Other pods stuck: "Volume already exclusively attached"

💡 The Solution:
Change to ReadWriteMany in BOTH PV and PVC!

⚠️  But here's the catch: You can't just edit the PVC...
You'll discover why when you try to apply the fix!

## Hint 3
✅ HINT 3: Complete Solution

Fix: Change accessModes from ReadWriteOnce to ReadWriteMany

📝 In PersistentVolume:
```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: shared-storage
spec:
  accessModes:
    - ReadWriteMany  # ✅ Changed from ReadWriteOnce
```

📝 In PersistentVolumeClaim:
```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: shared-pvc
spec:
  accessModes:
    - ReadWriteMany  # ✅ Changed from ReadWriteOnce
```

🚀 Apply:
```bash
# IMPORTANT: PVC spec is immutable - must delete and recreate!
kubectl delete deployment web-servers -n k8squest
kubectl delete pvc shared-pvc -n k8squest
kubectl delete pv shared-storage

# Apply the corrected configuration
kubectl apply -f solution.yaml

# Watch all 3 pods start successfully
kubectl get pods -n k8squest -l app=web -w
```

⚠️  **Why delete first?** PVC's accessModes cannot be changed after creation.
You must delete the PVC and PV, then recreate them with the correct access mode.

💡 Remember: Both PV and PVC must have matching access modes!
